# Toastive

A lightweight, accessible, fully customizable web component library for toast notifications — drop-in for **any** frontend stack.

- 🪶 Lightweight: ~6 KB gzipped, zero dependencies.
- ♿ Accessible: ARIA roles, keyboard support, focus management, prefers-reduced-motion.
- 🎨 Customizable: 30+ CSS variables to style every detail.
- 🚀 Easy to use: one function call — `showToastive(props)`.
- 📦 Zero dependencies: ESM-only, no runtime deps.
- 🌐 Framework-agnostic: vanilla web component, works with React, Vue, Svelte, Angular.
- ⏸ `pauseOnHover`: timer pauses on hover/focus.
- 🖐 Drag to dismiss: vertical drag toward the toast's corner.
- 🌈 Themes: 6 variants + light/dark color themes.

<br />

## 📦 Installation

```bash
npm install toastive
# or
pnpm add toastive
# or
yarn add toastive
```

<br />

## 🚀 Quick start

```javascript
import { showToastive, ToastivePosition, ToastiveVariant } from 'toastive'

showToastive({
  title: 'Saved',
  message: 'Your changes have been stored.',
  variant: ToastiveVariant.Success,
  position: ToastivePosition.TopRight
})
```

That's it — the toast appears, auto-closes after 5 s, and is fully accessible.

## 🌓 Theming

Each toast accepts `theme: ToastiveTheme.Light | ToastiveTheme.Dark`. The theme is **per toast** (it does not auto-detect from the OS), so you stay in full control. A global default can be set with `setDefaults({ theme: ToastiveTheme.Dark })`.

```javascript
import { showToastive, ToastiveTheme } from 'toastive'

showToastive({
  message: 'Looks good in dark mode too',
  theme: ToastiveTheme.Dark
})
```

## ⏱ Behaviors

### Auto-close & pause on hover

By default the toast auto-closes after `duration` (5 s). Hover or focus the toast to **pause** both the timer and the progress bar; move away to resume.

<Story of={ToastiveStories.pauseOnHover} />

Disable per toast:

```javascript
showToastive({
  message: 'Strict timer',
  pauseOnHover: false
})
```

### `prefers-reduced-motion`

If the user has reduced-motion enabled at the OS level, all slide/close animations are skipped. The toast appears and disappears instantly, the progress bar is hidden, and the drag-to-dismiss snap-back is removed. No opt-in required.

### Drag to dismiss

Every toast is draggable by default. Drag vertically toward the toast's corner — **up** for top-positioned toasts, **down** for bottom-positioned ones — past a 50 px threshold to dismiss. Reverse direction is ignored so the toast never opens the wrong way.

Disable per toast with `draggable: false`.

### Cap per corner (`maxVisible`)

Limit active toasts per position. When the cap is reached, the **oldest** toast is closed (FIFO) before the new one is added.

<Story of={ToastiveStories.maxVisible} />

Globally:

```javascript
import { setDefaults } from 'toastive'

setDefaults({ maxVisible: 5 }) // each corner holds at most 5 toasts
```

## 🧱 Patterns & recipes

Common end-to-end patterns with ready-to-copy snippets.

### Action button — Undo, Retry, View

Add a secondary button (typically "Undo", "Retry", "View"). By default, clicking it closes the toast. Pass `closeOnClick: false` to keep it open.

```javascript
showToastive({
  message: 'File deleted',
  variant: ToastiveVariant.Default,
  autoClose: false,
  closeButton: true,
  action: {
    label: 'Undo',
    onClick: () => restoreFile(),
    closeOnClick: true // default
  }
})
```

<Story of={ToastiveStories.actionButton} />

### Update a live toast — loading → success

`showToastive()` returns an instance with `update()` and `close()`. The DOM diffs in place — no re-creation, no animation restart (except `duration`, which restarts the progress bar).

```javascript
const toast = showToastive({
  title: 'Uploading',
  message: 'Please wait...',
  variant: ToastiveVariant.Loading,
  autoClose: false
})

await upload()

toast.update({
  title: 'Done',
  message: 'Upload complete.',
  variant: ToastiveVariant.Success,
  autoClose: true
})
```

<Story of={ToastiveStories.updateInPlace} />

### Global defaults

Use `setDefaults()` to apply options to every subsequent `showToastive()` call. Defaults are **merged**, not replaced — pass only the fields you want to change.

```javascript
import { setDefaults, ToastivePosition, ToastiveTheme } from 'toastive'

setDefaults({
  position: ToastivePosition.TopRight,
  duration: 3000,
  theme: ToastiveTheme.Dark
})
```

<Story of={ToastiveStories.globalDefaults} />

### Clearing toasts

Use `clearToasts()` to remove active toasts. Pass a position to scope the clear; omit to remove everything.

```javascript
import { clearToasts, ToastivePosition } from 'toastive'

clearToasts() // remove every toast
clearToasts(ToastivePosition.TopRight) // only top-right corner
```

<Story of={ToastiveStories.clearingToasts} />

### Custom icons

Pass an HTML string via `customIcon` to override the default per-variant icon.

```javascript
showToastive({
  message: 'Custom icon',
  customIcon: '<svg viewBox="0 0 24 24"><circle cx="12" cy="12" r="10" fill="currentColor"/></svg>'
})
```

## ♿ Accessibility

Toastive is accessible by default — no configuration required:

- **`role` & `aria-live`** are set on the host element based on variant (`polite` for info/success/loading, `assertive` for error/warning).
- **`aria-atomic="true"`** — screen readers re-announce the whole toast on each update.
- **Close button** has `aria-label="Close notification"`.
- **Keyboard support** — every toast is `tabindex="0"`. Tab to it, press <kbd>Esc</kbd> to close.
- **`prefers-reduced-motion`** — slide/close animations are skipped, drag snap-back removed, progress bar hidden.
- **Visible focus ring** on the toast when reached with the keyboard.

## 🌍 Framework integrations

Toastive is a Custom Element (`<mm-toastive>`) plus a one-call API. Because it ships as a Web Component, it works anywhere Custom Elements are supported. The only rule: **import `toastive` on the client side only** — it throws on SSR.

### Vanilla JS / TypeScript

```typescript
import { showToastive } from 'toastive'

document.querySelector('#save')?.addEventListener('click', () => {
  showToastive({ message: 'Saved!', variant: 'success' })
})
```

### React 19+

React 19 ships Custom Element support out of the box. The `showToastive` API uses no JSX, so there is nothing to wire up — just call it from a handler.

```tsx
import { showToastive, ToastiveVariant } from 'toastive'

export function SaveButton() {
  return (
    <button
      onClick={() =>
        showToastive({
          message: 'Saved!',
          variant: ToastiveVariant.Success
        })
      }
    >
      Save
    </button>
  )
}
```

> 💡 If you also render the element directly via `<mm-toastive>` in JSX, listen to its custom events with `addEventListener` inside `useEffect` — JSX-style props like `onToastiveClose` won't fire.

### Vue 3

```vue
<script setup lang="ts">
import { showToastive, ToastiveVariant } from 'toastive'

function onSave() {
  showToastive({ message: 'Saved!', variant: ToastiveVariant.Success })
}
</script>

<template>
  <button @click="onSave">Save</button>
</template>
```

### Angular 16+ (standalone components)

```typescript
import { Component } from '@angular/core'
import { showToastive, ToastiveVariant } from 'toastive'

@Component({
  selector: 'app-save',
  standalone: true,
  template: `<button (click)="onSave()">Save</button>`
})
export class SaveComponent {
  onSave() {
    showToastive({ message: 'Saved!', variant: ToastiveVariant.Success })
  }
}
```

### Svelte 5

```svelte
<script lang="ts">
  import { showToastive, ToastiveVariant } from 'toastive'

  function onSave() {
    showToastive({ message: 'Saved!', variant: ToastiveVariant.Success })
  }
</script>

<button onclick={onSave}>Save</button>
```

> 💡 Don't forget to add `toastive` to your bundler's `ssr.noExternal` / `external` config so the import is replaced by the client runtime on the server pass.

### `setDefaults(props)`

Merge defaults applied to every subsequent `showToastive()` call. Adds `maxVisible` — a per-position cap (oldest closed first).

```javascript
setDefaults({ maxVisible: 5, position: ToastivePosition.TopRight })
```

### `resetDefaults()`

Reset every default set by `setDefaults()` back to the package built-ins. Useful for tests or for cleaning up at runtime.

```javascript
setDefaults({ theme: ToastiveTheme.Dark })
// ...
resetDefaults() // back to built-ins
```

### `clearToasts(position?)`

Remove all toasts, or only the toasts in the given `ToastivePosition`.

```javascript
clearToasts() // everything
clearToasts(ToastivePosition.TopRight) // scoped
```

### `MmToastive` element

The underlying Web Component. You only need it if you want full markup control — otherwise `showToastive()` covers everything.

```html
<mm-toastive variant="success" auto-close position="bottom-right">
  <span slot="icon">⭐</span>
  <span slot="title">Saved</span>
  <span slot="message">Your changes have been stored.</span>
</mm-toastive>
```

It exposes the same properties as `showToastive()` plus `close()` and `update()` on the element instance.
